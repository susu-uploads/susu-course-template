# susu-course-template

Шаблон самостоятельного репозитория учебного курса для организации [susu-uploads](https://github.com/susu-uploads).

## Структура

```text
.
├── AGENTS.md
├── COURSE.md
├── README.md
├── .gitattributes
├── .gitignore
├── lecture/
│   └── lecture-1-lecture-title/
│       └── .gitkeep
└── practice/
    └── practice-1-assignment-title/
        ├── .gitignore
        └── TASK.md
```

`lecture-1-lecture-title` и `practice-1-assignment-title` — примеры каталогов. При создании курса переименуйте их по данным источника либо удалите, если соответствующих материалов нет. `.gitkeep` сохраняет пустой каталог в Git; после добавления материалов его можно удалить.

## Создание курса

1. Создайте репозиторий через **Use this template**. Назовите его `<EnglishAcronym>-<YYYY>`: аббревиатура английского названия курса и год, без префиксов программы и формы обучения. Разрешены только английские буквы, цифры и дефисы.
2. Клонируйте новый репозиторий и включите Git LFS до добавления вложений:

   ```sh
   git lfs install --local
   ```

3. В `README.md` укажите русское и английское названия курса. Заполните `COURSE.md` и каждый `TASK.md` четырьмя строковыми полями `ru`, `en`, `code`, `origin`. Пустые значения в шаблоне — места для данных первоисточника; в заполненных карточках они не должны оставаться пустыми.
4. Перенесите учебное содержание Moodle в Markdown полностью, сохраняя язык, формулировки, порядок и ссылки. В `COURSE.md` сохраните описание, преподавателей, правила оценки и разделы с элементами курса. В каждом `TASK.md` оставьте `Источник задания`; добавьте `Задание`, если описание существует. Исключите интерфейс, личные оценки, ответы, комментарии, статусы выполнения и сессионные данные.
5. Разместите материалы в `lecture/lecture-<number>-<english-title>` и `practice/practice-<number>-<english-title>`. Сохраните исходную нумерацию, имена и содержимое файлов. Внутри каждой лекции или практики храните файлы плоско, вместе с существующими решениями.
6. Обновите корневой `.gitignore` одним ответом [Toptal](https://www.toptal.com/developers/gitignore?templates=macos,windows,linux,jetbrains,visualstudiocode), добавив теги фактически используемых инструментов. Сохраняйте ответ генератора без изменений. Пользовательские исключения задавайте только в `.gitignore` соответствующей практики или лекции; временные `.cache/` и `.report/` должны игнорироваться.

## Литература

| Материалы первоисточника | Что создать |
|---|---|
| Литература не указана | Ни `library`, ни `LIBRARY.md` |
| Только названия или ссылки | Корневой `LIBRARY.md` с таблицей названий и ссылок, без `library` |
| Названия или ссылки вместе с файлами книг | Корневой `LIBRARY.md` и файлы книг внутри `library` |

## Проверка

Проверьте frontmatter, соответствие кодов именам каталогов, ссылки источников и полноту экспортированного текста. У каждой практики должен быть `TASK.md`; при повторной выгрузке сохраняйте вложения и пользовательские решения.

```sh
git diff --check
git lfs fsck
git check-ignore -v practice/practice-1-assignment-title/.cache/example
```

В последней проверке используйте фактический каталог практики. Карточки, исходные материалы и итоговые решения должны оставаться доступными Git.

Шаблон содержит настройки LFS, но не двоичные материалы: [GitHub не переносит LFS-файлы из шаблонных репозиториев](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-template-repository). Вложения добавляются уже в созданный репозиторий курса.
